## Goal
Build the **backend extraction-verification library**: given a resolved full-text source and a
target set of efficacy outcomes, extract each numeric datum and assign it a status —
`verified` / `check` / `manual` — where **`verified` requires ALL FOUR independent checks to
pass**, each value carrying its provenance. Backend only; UI, author-contact, and figure
handling are deferred (§ out-of-scope).

## The 4-check gate (a value is `verified` only if all pass)
1. **Source-presence gate** — the number appears **character-for-character in that page's own
   text layer** (reading-order + layout + parsed table grids). A number on a *different* page →
   `wrong_page` (mis-citation), not `not_in_source` (fabrication) — distinct failure codes. A
   spelled-out number ("forty-two") is flagged, not treated as fabrication.
2. **Two differently-framed passes agree** — a cell-by-cell transcriber vs a target-hunting
   pass; disagreement → `conflict:<field>`, **never averaged**. (This is **AI-assisted**, NOT
   dual-independent extraction per Cochrane §5.5.2 — label it so; two passes of one model ≠ two
   people.)
3. **Internal consistency** (Cochrane §6.3.1, §6.5.2.2–3): `SE≈(CI_hi−CI_lo)/3.92`
   (t-divisor when n<60); `SD≈SE·√n`; `%≈events/total`; `mean ∈ [CI_lo,CI_hi]`; CI order; `n ≤
   randomised`.
4. **Range check** — value is possible for the instrument (e.g. MADRS 0–60).
Anything failing a check → `check` (human reads it); anything the tool refuses → `manual`.

## Provenance & rules (Cochrane Ch 5 §5.2.3/§5.7)
- Store **source-reported values separate from any calculated value**; log every calculation
  with its Cochrane cite; **no silent conversion** (SE→SD, endpoint→change belong in analysis,
  not extraction). Record **where each value came from** (page, table/figure) + capture the
  verbatim strip location so the UI (later) can show the cropped evidence.
- **Store by row identity** so decisions survive re-extraction. Human-reviewed → `human`, never
  `verified`.
- **No values digitised from figures** here → status `author_contact` (operator rule; Cochrane
  §5.5.8 allows software digitising — but defer that).

## Acceptance criteria ("beat, don't match")
- **AC1:** a fabricated number (not in the page text) is NEVER `verified` (→ `not_in_source`). Unit-proven.
- **AC2:** the Ch 6 formulas are implemented exactly and unit-tested against worked examples (SE from 95% CI; SD from SE·√n; t-divisor for n<60).
- **AC3:** every returned value carries non-null provenance (page + source_text) or a failure code.
- **AC4:** two-pass disagreement yields `conflict`, never an averaged value.
- **AC5 (tester, external):** run against ≥3 trials from the **ketamine/TRD truth set**
  (`[[Field Report — Ketamine TRD Review]]` §2) where the reported numbers are known; measure
  extraction accuracy + false-`verified` rate (must be 0). Stays `claimed` until validated.
- **AC6:** gates green — `npm run lint`, `npm test`, `npm run build`; no screening regression.

## Decision (operator session, 2026-10-13) — PDF text-layer library
Use **`unpdf@1.8.1`** (MIT, zero dependencies, serverless/Vercel-ready, bundles Mozilla pdf.js).
Use `extractText(pdfBytes, { mergePages: false })` to get **per-page** text, then feed it to the
existing page splitter / source-presence gate. Pin the exact version. Fetch the PDF bytes from the
URL that `resolveFulltext` returns (open-access only; respect the existing no-paywall rule), and
add `doi`/`pmid` input to `/api/extract` so a caller can extract straight from an identifier.
Scanned (image-only) PDFs have no text layer → return `manual` with reason `no_text_layer`; no OCR
in this slice. Rejected alternative: `pdfjs-dist` (heavier; worker/canvas setup on serverless).

## Real-PDF smoke test (operator session, 2026-10-13) — inputs for the AC5 tester run
`unpdf` on Pattanaseri 2024 (BMC Psychiatry, CC BY, 11 pages) gave clean per-page text. Day-10
MADRS row (p6): ketamine 12.55 (SE 2.64, 95% CI 6.70-18.09) vs midazolam 17.22 (SE 2.92, 95% CI
11.09–23.36). Use as AC5 cases: (a) source presence must find 12.55/17.22 on p1+p6; (b) the same
document mixes ASCII hyphen and en dash in CIs — the validation 010 limitation, now seen on a real
trial; (c) SE 2.64 vs CI width/3.92 ≈ 2.91 should NOT pass consistency → `check` (matches the field
report's "wrong-day SEs" note) — a correct `check`, never `verified`.
