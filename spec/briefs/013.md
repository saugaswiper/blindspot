## Acceptance criteria (beat, don't match)
Mark AC1–AC2 `claimed` until a tester run measures them on reviews the model never saw.
1. **AC1 — beats random and beats the in-review baseline at cold start.** On held-out reviews (≥5 SYNERGY reviews excluded from training, plus Mitchell 2012 if its records are available): mean WSS@95 **≥ 0.20 absolute** and **> 0 on every held-out review**, with zero labelled records from that review given to the model. Report per review and mean. Also report the flat-0.5 cold-start WSS@95 (≈0) as the baseline to beat.
2. **AC2 — recall early.** Mean recall at 20% screened **≥ 0.60** on the same held-out set (random ≈ 0.20). Report the number honestly if missed; do not tune hyperparameters on the held-out reviews.
3. **AC3 — zero leakage.** A unit test asserts no review ID appears in both train and held-out; the artifact manifest lists both sets.
4. **AC4 — no text in the artifact.** A unit test scans `v1.json` and fails if it contains any record title/abstract (check by length-of-string and n-gram overlap with a fixture abstract). Vocabulary terms are allowed; artifact size ≤ 5 MB.
5. **AC5 — determinism and no regression.** Same input gives byte-identical scores; once the cold start is exercised, behaviour with ≥1 include and ≥1 exclude is identical to before this brief (existing `screening-ranker.test.ts` passes untouched).
6. **AC6 — promotion rule recorded** in the artifact metrics and the script header: v(N+1) replaces v1 only if it beats v1 on the same held-out set (tester gate); training uses only published labels, never the model's own predictions.
7. Gates green: `npm run lint`, `npm test`, `npm run build`; train script documented with exact run commands in its header.
