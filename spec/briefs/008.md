# Brief 008 — EuropePMC Cursor Pagination: Full-Result Retrieval in `fetchPrimaryStudyIds`

**Date:** 2026-08-09
**Stage in pipeline:** Stage 2 — Literature search (primary-literature capture)
**Status:** UNBLOCKED — pure code fix, no ops/secrets dependency

---

## Goal

Replace the current single-page 200-record EuropePMC fetch in `lib/europepmc.ts`
`fetchPrimaryStudyIds` with a `cursorMark`-based pagination loop that collects up to
2 000 records. The cursor mechanism was confirmed working by validation 006 Probe C2
(cursor advances between pages, no infinite loop). The production code currently
retrieves <10% of available results for a typical topic query.

---

## Why now

Validation 006 F3 (High, Carried from 005 F4) confirmed EuropePMC's date-sorted
185-record window systematically excludes papers published before the most recent ~185
publications in the result set. For the Mitchell 2012 truth set:

- EPMC `hitCount` = 1994 for "cognitive behavioral therapy insomnia"
- Production code returns 185 records (page 1 of 10)
- Truth papers from 1991–2006 are in pages 8–10 (~positions 1 400–1 994)
- EuropePMC recall = **0/5 (0%)** — entirely due to truncation, not to the filter or index

The `NOT PUB_TYPE:"Systematic Review"` filter was confirmed working (1994 vs ~3000+
unfiltered results); the issue is purely depth. For queries where PubMed and EPMC cover
overlapping papers, the 0/5 EPMC result is masked by PubMed's 4/5. But for topics where
relevant RCTs are EPMC-unique — preprints, European trial registers, non-MEDLINE journals
— the current 185-record cap silently drops them from the union.

Validation 006 §8 step #2 names this as the next dev task after the sibling-function fix
(shipped in handoff 107). The Stage 3 production union recall ≥95% claim remains
**contradicted** (current: 80%) and this fix is the next unblocked step toward closing
that gap.

**CRIT-1 (OpenAlex api_key 401) is blocked on ops action** — noted here, not coded.

### The cursor loop

Validation 006 Probe C2 confirmed:
- Page 1: `cursorMark=*`, returns 200 records, `nextCursorMark=AoIIQHnX7ig1MjgyMjAwMA==`
- Page 2: `cursorMark={nextCursorMark from page 1}`, returns 181 records, new `nextCursorMark`
- Cursors are distinct between pages (no infinite loop)

Implement as follows:

```ts
// In fetchPrimaryStudyIds, replace the single-page fetch with:
const ceiling = Math.min(limit, 2000);
const pageSize = 200;
const collected: string[] = [];
let cursor = "*";

while (collected.length < ceiling) {
  const url = new URL("https://www.ebi.ac.uk/europepmc/webservices/rest/search");
  url.searchParams.set("query", builtQuery);      // existing query construction
  url.searchParams.set("resultType", "idlist");
  url.searchParams.set("pageSize", String(pageSize));
  url.searchParams.set("cursorMark", cursor);
  url.searchParams.set("format", "json");
  // Do NOT set a sort parameter — sort=RELEVANCE is deprecated (validation 005 F5);
  // default date sort is fine with full pagination.

  const res = await fetch(url.toString());
  const data: EuropePMCResponse = await res.json();

  const ids = (data.resultList?.result ?? []).map((r) => r.pmid ?? r.id).filter(Boolean);
  collected.push(...ids.slice(0, ceiling - collected.length));

  const next = data.nextCursorMark;
  if (!next || next === cursor || ids.length === 0) break;  // end of results
  cursor = next;
}

return collected;
```

Key invariants:
- **Ceiling 2 000** — matches PubMed and OpenAlex ceilings set in handoffs 105/106.
- **Break conditions**: (a) collected ≥ ceiling; (b) no `nextCursorMark`; (c) cursor
  unchanged from previous page (API signals end of pagination); (d) empty page.
- **No sort param** — `RELEVANCE` is invalid (validation 005 F5); default date sort with
  full coverage is the correct approach.
- **`EuropePMCResponse` interface** — add `nextCursorMark?: string` at the top level if
  it does not already exist. The field is returned by the live API (confirmed Probe C2).

## Notes for the dev

**Why no sort param:** EuropePMC's `sort=RELEVANCE` was deprecated between validations
004 and 005 — it now returns `{"version":"6.9"}` with zero results (validation 005 F5).
Production code already omits the sort param (defaulting to date sort). Keep it that way.
With full cursor pagination through all 1994 results, date sort is irrelevant — every record
is retrieved regardless of position.

**`nextCursorMark` field location:** Validation 006 Probe C2 confirmed the field is at the
top level of the EPMC JSON response (not nested inside `resultList`). If the
`EuropePMCResponse` type does not already include it, add `nextCursorMark?: string` to the
interface.

**Rate limiting:** EuropePMC's REST API has a polite limit (~10 req/s for registered
emails). At 10 pages of 200 records each, 10 requests/query is well within normal usage.
No throttle or delay is needed for this ceiling. If the codebase already passes an email
header for polite access, keep it; otherwise leave the fetch as-is.

**Interaction with CRIT-1:** After CRIT-1 is resolved (OpenAlex api_key), OpenAlex will
also contribute up to 4/5 recall independently. At that point, EPMC's contribution to the
union may be additive or redundant depending on the query. The union logic (deduplication
by PMID) already handles overlap; no change needed here.

**Post-fix validation:** The tester will write validation 007. Expected outcome:
- EPMC `fetchPrimaryStudyIds` returns ~1900–1994 IDs for the test query
- EPMC hits ≥2/5 truth papers on Mitchell 2012 (papers from 1999–2006 now accessible)
- Union recall: PubMed(4/5) + EPMC(≥2/5, deduped) = still 4/5 on Mitchell 2012
  (same papers found by PubMed; but EPMC now independently confirms them)
- Tester should also probe a second topic (e.g., exercise + depression, recent SR) to
  confirm EPMC pagination generalises beyond Mitchell 2012
