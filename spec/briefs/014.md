# Brief 014 — Screening workbench: discoverable, scoped keyboard speed mode (active row)

**Track:** design
**Source:** spec/design/003 §S6 (remaining half: keyboard-opaque rows; the `cursor-pointer` and "Speed mode" label halves shipped in handoff 093)
**Priority:** after FAIL-fixes and Priority NEXT (brief 013 first)
**Date:** 2026-11-02
**Blockers:** none (UI only, no secrets, no ops). A live pixel pass still needs a seeded owned result with 3,000+ decisions (design 003 "Verification basis"); the component tests below do not.

## Goal
At 3,000+ records the reviewer lives in `j/k/y/n/u/r`. Today the active row is invisible until a first key press, rows are not reachable by Tab, the active outline uses `--accent` with no stated contrast, and `ArrowUp/ArrowDown` are `preventDefault`ed on the whole `window` even when no row is active, so page scrolling breaks anywhere on the results page while the panel is mounted. Make speed mode visible, announced, and scoped, without changing what any key does to a verdict.

## Scope
**In** (one component, one section: the results-table row list in `ScreeningPanel.tsx`)
1. **Scoped key handling.** `ArrowUp/ArrowDown/j/k/y/n/u/r` act only when the keydown target is inside the panel's own results region (ref `contains`), or is `document.body` while a row is already active. Otherwise do nothing and do **not** `preventDefault`. Existing guards for INPUT/TEXTAREA/SELECT/contenteditable and meta/ctrl/alt stay.
2. **Rows are keyboard-reachable.** One roving tab stop: the active row (or row 0 if none) has `tabIndex={0}`, others `-1`. Use `role="list"` / `role="listitem"` (native semantics, no custom listbox). Focusing a row via Tab or click makes it active. `Escape` returns focus to the toolbar and clears the active row.
3. **Active-row affordance.** Replace the `2px solid var(--accent)` outline with `var(--ring)` plus `aria-current="true"` on the active row. The outline is not the only cue: the "Speed mode" hint shows `Row N of M` while a row is active.
4. **Announce the effect of y/n/u.** One visually-hidden `role="status"` `aria-live="polite"` region states the result of a verdict, e.g. `Row 12 of 3,042: Include recorded` or `Row 12 of 3,042: human decision cleared`. One message per action, not per render.
5. **No auto-recording from focus.** Activating a row (click, Tab, `j/k`) never records a verdict. Do not auto-activate row 0 on mount: an unseen first row must not receive a stray `y`. When no row is active the hint reads "Press j to start".

**Out**
- S5 (collapsing the 3× verdict restatement), S10 (idle CTA), list virtualisation, changing which key does what, new keys, any API/ranker change, `KeyboardShortcutsHelp` content. The AI verdict, confidence bar, "✓ Human" badge, retraction badge and any `check`/`manual`/`claimed` marker must not be hidden, shortened or reordered.

## Acceptance criteria
Mark each `claimed` until the tester verifies.
1. **Scoped keys.** With focus on `document.body` and no active row, or focus outside the results region, `ArrowDown`/`ArrowUp`/`j`/`k` leave `event.defaultPrevented === false` and the page scrolls natively. Inside the region they navigate. Test covers both.
2. **Keyboard path.** From the toolbar, Tab reaches exactly one row stop (not 3,000); `j/k` move it; `y/n/u` record on the active row only; `r` toggles reasoning; `Escape` returns focus to the toolbar; Shift+Tab leaves the list in one press (no trap, WCAG 2.1.2).
3. **Focus visibility + target size.** Active outline is `var(--ring)`, ≥ 2 px, ≥ 3:1 against `--surface` in light and dark (report both ratios in the handoff; WCAG 1.4.11, 2.4.7, 2.4.11 not obscured by any sticky bar). Verdict buttons stay ≥ 28 × 28 px (WCAG 2.5.8). `aria-current="true"` is on exactly one row when active, none otherwise.
4. **Announcements.** A keyed or clicked verdict yields exactly one status message with row position, total, and verdict recorded/cleared. Test asserts text and count.
5. **No accidental decisions.** Mounting 3,000 mock decisions and activating a row by click, Tab, and `j/k` produces zero `onOverride` calls until `y/n/u` is pressed.
6. **Methodology states preserved.** DOM assertion that each row still renders the AI verdict badge, confidence bar, "✓ Human" badge when set, retraction badge when set, and `check`/`manual`/`claimed` markers, identical to before.
7. **Responsive + themes.** At 400 px and 1280 px, light and dark: no horizontal page scroll introduced, the hint wraps rather than truncates, row layout otherwise unchanged. Before/after screenshots in the handoff, or `[live-pending]` if the seed-data blocker stands.
8. **Performance.** At 3,000 decisions with existing `PAGE_SIZE` paging, renders per `j` keypress are no worse than baseline (state the measured count).
9. **Gate.** `tsc --noEmit` and `eslint components/ScreeningPanel.tsx` both exit 0.
