# Brief 010 — ML Layer v0: Screening Prioritization Model + Held-Out Benchmark

**Date:** 2026-10-12
**Stage in pipeline:** Stage 3 — Title/abstract screening (ML layer, first target)
**Status:** UNBLOCKED (no secrets). Queued **after brief 009** (extraction is top priority).
**Grounded in:** wiki `[[ML Layer]]` (design + licences), `[[Validation Strategy]]`, `[[Screening]]`
(operator requirement: screen 3,000+ records).

## Goal
Ship the first trained model in Blindspot: rank screening records by inclusion probability so a
reviewer sees likely-includes first, plus a **stopping-criterion estimate** of recall reached. Build
the **held-out benchmark harness** that every future model must beat before promotion — this is
the gate that makes later "recursive" retraining safe.

## Why now
- Screening 3,000+ records is an operator requirement; ranking + a stopping rule is what makes
  that workload practical (ASReview-style; WSS@95 is the standard metric).
- Today "active learning" is in-context only (`lib/screening.ts:312`); nothing is trained.

## Data (licences checked — see [[ML Layer]])
- **Train:** SYNERGY (CC0; 26 SRs, 169k records, 2,834 includes). Cite De Bruin et al. 2023.
- **Held-out eval:** CLEF TAR (internal research use only — MIT covers software, not data; no
  redistribution) + Mitchell 2012 + ketamine/TRD truth sets. **Never train on held-out reviews.**
- **Split by review, not by record** (no leakage). Do not commit abstract text or ship it inside the
  model artifact (PubMed abstracts may be publisher-copyrighted) — commit IDs + a fetch script.

## Approach (default; dev may justify a change)
- Features: TF-IDF over title+abstract (no external API, deterministic). Embeddings are a later option.
- Model: logistic regression (or naive Bayes baseline) — the ASReview baseline that performs well.
- Training runs **offline as a script** (`scripts/train-screening-model.ts`); output is a
  **versioned JSON artifact** (`models/screening/vN.json`: vocab, weights, training-data manifest,
  metrics). Inference in Node (`lib/screening-ranker.ts`) — no Python service, no new infra.
- Per-review **cold start**: until the reviewer has ≥1 include and ≥1 exclude, use the global
  model; after that, an in-review active-learning update (retrain on that review's verified
  verdicts, in memory) re-ranks the remainder.

## Acceptance criteria ("beat, don't match")
- **AC1:** On held-out reviews, WSS@95 > 0 vs random order and ≥ the ASReview published baseline
  for the same reviews where comparable. Report per review + mean. (Tester verifies → stays `claimed` until then.)
- **AC2:** Zero leakage — unit test asserts no review appears in both train and held-out.
- **AC3:** The artifact contains no abstract/title text (unit test scans it).
- **AC4:** The stopping estimate is reported with its uncertainty and is **advisory only** — it never
  auto-excludes records (RAISE: humans decide; recall is paramount).
- **AC5:** Promotion rule recorded: a future v(N+1) replaces vN only if it beats vN on the same
  held-out benchmark (tester gate). Training uses **only** published labels or human-verified
  verdicts — never the model's own predictions.
- **AC6:** Gates green: `npm run lint`, `npm test`, `npm run build`; no screening regression.
