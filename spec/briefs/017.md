# Brief 017 — Stopping rule that fires + ranker fast enough for 3,000+ (validation 016 follow-up)

**Priority:** NEXT
**Date:** 2026-11-03 (operator-written)
**Stage in pipeline:** Title/abstract screening, ML layer. Supersedes the stopping-rule part of brief 013, whose acceptance criteria stay unmet.
**Evidence:** validation 016 §2D/§2E and handoff 132.
- On Set B the brief 013 Poisson lower bound **never** reached 0.95 in 4/4 runs, though true recall hit 95% at 34.5–47.9% screened.
- `rankRecords` costs about 2 s per call at n ≈ 1,000, with about 60 calls per review. The 22-review scorecard (brief 015) cannot be produced.

**Blockers:** none.

## Goal
1. A stopping rule that is **valid and fires**. Replace the score-sum bound with a statistical stopping test that doesn't depend on model calibration.
2. `rankRecords` fast enough that a full simulated review at n = 3,000 runs in minutes, and n = 49k is feasible.

Both live in `lib/screening-ranker.ts`. Do (1) first; if the run gets long, ship (1) and leave (2) for the next run.

## Why the old approach failed (operator diagnosis; dev may refute it with data)
Summing uncalibrated LR scores over thousands of unscreened records gives a large expected-missed count, even when each score is small. A Poisson upper quantile on that sum makes the lower bound sit far below the truth. The audit ratio is clamped ≥ 1 and drawn from the head of the ranking, so it can't pull the sum down. Calibrating scores is the wrong lever. The literature uses tests on what the reviewer actually observed.

## Scope
**In: (1) stopping rule**
- Implement the **hypergeometric stopping test** of Callaghan & Müller-Hansen 2020 (*Systematic Reviews* 9:273, "Statistical stopping criteria for automated screening in systematic reviews"):
  - Treat the last k records screened in ranked order, after a minimum screened fraction, as a sample from the unscreened tail under H0: recall < target.
  - Compute the p-value with the hypergeometric distribution.
  - Stop when p < α, with defaults target 0.95 and α 0.05.
  - The dev must read the paper's method section and cite the equation implemented in a code comment. If it can't be accessed, say so in the handoff and implement the hypergeometric test as described there from first principles, with the derivation in the comment.
- New export, e.g. `stoppingTest(screenedInOrder: boolean[], nTotal, { target, alpha }) → { stop: boolean, p: number, recallLowerBound: number, kUsed: number, method: "hypergeometric-cmh2020", advisory: true }`.
- Keep `estimateRecall` exported for compatibility, but mark it deprecated as a stopping signal in its doc comment.
- Optional and cheap: also report the **knee method** (Cormack & Grossman 2016) as a second, heuristic signal labelled `heuristic`. Never use it alone to say "safe to stop".
- Update `lib/screening-benchmark-sim.ts` `activeLearningRun` to record the hypergeometric stop point: % screened, true recall at the stop, and whether true recall ≥ target. Keep the old estimate's fields as they are, for comparison.

**In: (2) latency**
- Vectorise once: memoise TF-IDF vectors per records array, for example with a `WeakMap` keyed on the array or an explicit `createRanker(records)` with `rank(verdicts)`. `rankRecords(records, verdicts)` keeps its signature and behaviour.
- Use dense or typed-array weights instead of `Map<string, number>` in `fit`. Warm-start from the previous round's weights when called through the ranker instance. Cap epochs, or stop early on loss change.
- **Class balance:** weight positives by `nNeg/nPos`, or use ASReview-style dynamic resampling. Justify the choice. The ranking must not get worse on SYNERGY (validation 015 harness: mean WSS@95 0.51).

**Out**
- UI, routes, brief 015 conditions C, D and E (the next dev run after this one).
- Any auto-exclusion: the output stays advisory.

## Acceptance criteria (all `claimed` until the tester reruns)
1. **Fires and is safe on Set B.** Use the brief 015 condition B protocol with seed 1 on at least the 8 smallest Set B reviews, then all 22 if (2) makes it feasible.
   - The hypergeometric test stops in at least 7 of 8 reviews before 100% is screened.
   - True recall at the stop is ≥ 0.95 in at least 7 of 8. Any miss is listed by review.
   - Report the median % screened at the stop.
2. **Valid on SYNERGY.** On the validation 015 protocol (9 reviews, seeds 1–3), true recall at the stop is ≥ 0.95 in at least 95% of runs, with the stop at most 70% screened in at least 7 of 9 reviews. This is brief 013's AC1 bar, now applied to the new test.
3. **Latency.** A full condition-B simulated run at n = 3,000 completes in ≤ 3 minutes on the dev machine, and per-call `rankRecords` at n = 3,000 is ≤ 300 ms after warm-up. State the n = 49k figure measured or projected, and say which.
4. **No ranking regression.** SYNERGY mean WSS@95 ≥ 0.49 (validation 015 baseline 0.51, minus noise), reported per review.
5. **Unit tests:**
   - the hypergeometric p-value matches a reference value, either hand-computed or the paper's worked example;
   - the test never stops before the minimum screened fraction;
   - an all-negative tail eventually triggers a stop;
   - an include in the last k blocks the stop;
   - memoised and non-memoised ranking give identical orders for the same inputs.
6. **Gates:** lint, test and build are green, with only the known 12 baseline failures.

## Risk
If (2) changes ranking order materially (warm-start or class balance), AC4 decides. Revert the change that causes the regression rather than lowering the bar.
