# Brief 015 — Realistic screening benchmark (Cochrane Set B scorecard)

**Date:** 2026-11-03
**Stage in pipeline:** Title/abstract screening, ML layer (build order ③; phase 1 of wiki `[[Screening Model Plan]]`)
**Depends on:** brief 013 merged. This brief measures 013's new `estimateRecall` on realistic data. If 013 is not on `main`, stop and say so in the handoff.
**Blockers:** none. The dataset is public, CC BY 4.0, and needs no login. Gemini use is capped (AC6).
**Operator intent:** every future screening model, including the GPU-trained protocol model (phase 2), must beat this scorecard before it ships. This brief builds the bar, not a model.

## Goal
Produce one reproducible scorecard showing how Blindspot's screening performs on **real search output at real imbalance**, at the operator's 3,000+ records requirement. Use the 22 Cochrane reviews whose searches were re-run (Chan et al. 2025, "Set B"). Measure:
- the ranker we ship,
- a **zero-label protocol cold start**,
- the stopping rule,
- a capped Gemini zero-shot sample.

## Why now
- Validation 015 tested on 9 SYNERGY reviews of 258–1,630 records. Users will screen 3,000+ records with about 1% includes. Set B is that case, with real Cochrane adjudication.
- Chan 2025 reports 19/22 Set B reviews at ≥95% recall with a BioBERT model (`claimed`). We need our own numbers on the same reviews before deciding whether a GPU-trained model is worth it.
- Competitor edge: ASReview needs prior labels before ranking works. A protocol cold start would rank from record 1. This brief tests the cheap version (TF-IDF) before any GPU work.

## Scope
**In**
1. `scripts/fetch-chan2025-setb.ts`
   - Downloads and verifies the zip to the cache. Idempotent.
   - Fallback: if the download is blocked, accept `--from <local zip>` and record that in the handoff.
   - Never bypass a bot check.
2. `lib/screening-benchmark-setb.ts`, a loader that normalises each review to `{ reviewId, protocol: { title, objectives, criteria }, records: [{ id, title, abstract|null, label }] }`.
3. **Held-out manifest:** `models/heldout/chan2025-setb.json`.
   - Contents: the 22 review IDs, which are never to be trained on, plus the dataset DOI and sha256.
   - Phase 2 training must exclude them, including other versions of the same CD number.
4. **Harness:** `scripts/benchmark-setb.ts`, writing `spec/benchmarks/015-setb-scorecard.json` plus a short `.md` summary. Conditions, per review:
   - **A. Random order:** floor reference, 3 seeds.
   - **B. Current active learning:** `rankRecords` with a 1 include + 1 exclude prior and the validation 015 protocol (batch = max(10, n/60), seeds 1–3).
   - **C. Protocol cold start:** rank by TF-IDF cosine between the review's protocol text (title, objectives and selection criteria) and title+abstract. Zero labels. Then the same active learning as B, with C's order used before the first labels.
   - **D. C+B fused:** the cold-start score as the prior that active learning updates. A simple choice (cosine as an extra LR feature) is fine; justify it in the handoff.
   - **E. Gemini zero-shot sample:** the existing `lib/screening.ts` path, capped by AC6.
5. **Stopping rule on real data:** run brief 013's `estimateRecall` along conditions B and D. Record the % screened at the stop point and the true recall there.
6. **Robustness slices:**
   - per review;
   - records with no abstract (count, and their rank distribution versus includes);
   - reviews flagged diagnostic-test-accuracy (DTA), which Chan 2025 found hardest.

**Out**
- Model training, Python, the GPU, transformers.js, UI changes, route wiring, Set A, and any change to `rankRecords` or `estimateRecall` behaviour.
- If B is too slow at real n, record it. Do not optimise here; brief 013 owns latency.

## Acceptance criteria (all `claimed` until the tester reruns)
1. **Reproducible.** One command fetches, verifies and benchmarks. A rerun with the same seeds gives identical numbers for A–D.
2. **Metrics per review and condition:**
   - WSS@95;
   - recall@10%, @20% and @30% screened;
   - % screened to reach 95% recall (and 98% where feasible);
   - for the stopping rule: % screened at stop, true recall at stop, and whether the lower bound held.

   Report the **median, the worst review and the mean**, never the mean alone.
3. **The decision the scorecard must answer:**
   - Does C beat B on recall@10% (the first 10% of the pool, before labels pay off)?
   - Does D beat B on WSS@95?
   - State yes/no with the per-review counts. A negative result is a valid outcome; report it plainly.
4. **Stopping-rule safety at scale:** the share of reviews where the 013 stop point has true recall < 0.95. Any such review is listed by name, with whether it is DTA.
5. **Comparison row:** a row with Chan 2025's Set B figures, labelled `claimed (paper)`, next to ours. Compare only on matching metrics, and note any mismatch.
6. **Gemini cap:**
   - At most 3 reviews: the smallest, the median-size one and one DTA review if present.
   - All includes plus at most 300 random excludes each, and **≤ 1,500 records in total**.
   - Abort if the cap would be exceeded.
   - Report sensitivity and specificity on the sample, and the number of calls made.
7. **Hygiene:**
   - A test scans committed files under `models/` and `spec/benchmarks/` and fails if they contain any record title or abstract string from the loaded data. Run it locally against the cache; on CI, skip it when the cache is absent.
   - `npm run lint`, `npm test` and `npm run build` are green, with no new failures beyond the known baseline.
8. **Latency recorded:** wall-clock time for `rankRecords` per call at each review's real n. This is the input to brief 013's budget and to phase 3's browser budget.

## Risks
- **Licence:** CC BY 4.0 requires attribution in the scorecard `.md` and later in any UI that shows these benchmark numbers.
- **Leakage:** Set B reviews also appear in Set A, possibly as other versions. The manifest exists to stop phase 2 leakage, so key it by CD number, not by title.
- **Label definitions:** the paper's "total recall" and its false-positive definitions may differ from ours. Define every metric in the `.md`.
- **Mac CPU only:** if a full B run over all 22 reviews exceeds about 2 h, run seeds 1–3 on the 8 smallest and seed 1 on the rest. Say which.
